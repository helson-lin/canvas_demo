## 做了什么
- `src/persistence/db.ts`：idb-keyval 自定义 store（db `canvas-demo`，objectStore `kv`），键 `doc`、`blob:<key>`；`listBlobKeys()` 供 GC；`resetDbForTests()`（仅测试）。
- `src/persistence/persist.ts`：
  - 启动：读 doc → `migrate` → `repairDocument`（删悬空边；清除指向不存在任务的 `pendingTaskId`；`activeTaskId` 指向不存在任务时置 null）→ `replaceDoc` → 开启保存 → `await resumeTasks()` → `setHydrated(true)`。无存档则空画布。
  - `initPersistence()` 幂等（StrictMode 双调用安全）。
  - `UnsupportedVersionError` / 数据无法解析 / 读取失败：toast，空画布启动，**本会话禁用保存**，存储不被覆盖。
  - 保存：订阅 store，`doc` 引用变化 → `scheduleSave()`（300ms debounce）；`saveNow()` 清除 debounce 并立即入队，Promise 在写入完成后 resolve；写入通过 Promise 队列串行化（快照在入队时捕获，FIFO，不会旧覆盖新）；与上次写入同一引用时跳过。只写 `doc`。`visibilitychange=hidden`、`pagehide` 时 flush。
  - 每次写入 `setSaveStatus('saving' → 'saved' | 'error')`；失败时 toast 并让 `saveNow()` reject（队列继续可用）。
  - 水合前 `saveNow/scheduleSave` 为空操作。
- `src/domain/migrations.ts`：v0→v1 真实迁移：补 `version`；缺 `kind` 的边：源为 generator → `'result'`，否则 `'input'`；缺失的 `viewport/nodes/edges/assets/tasks` 补默认值。非对象输入抛错；未来版本抛 `UnsupportedVersionError`。保持纯净。
- `src/services/assetStore.ts`：`importFile`、`persistRemote`、`useAssetUrl`、新增 `gcBlobs()`。尺寸通过 `createImageBitmap`（可用时）获取，失败则省略。

## 对外暴露的接口（签名）
- `persistence: PersistenceAdapter`、`initPersistence(): Promise<void>`、`setSaveStatus`、`useSaveStatus`（签名未变）
- `repairDocument(doc: CanvasDocument): CanvasDocument`、`SAVE_DEBOUNCE_MS = 300`、`resetPersistenceForTests()`（仅测试）
- `importFile(file: File): Promise<string>` — Blob 落盘 → upsertAsset(upload) → `await saveNow()` → 返回 assetId
- `persistRemote(url, originTaskId): Promise<string>` — fetch（非 2xx 抛错）→ Blob 落盘 → upsertAsset(generated, origin) → 返回 assetId。**不调用 saveNow**：T4 应随后在同一个 `transact` 中设置节点 `assetId`、清 `pendingTaskId`、任务 `succeeded`，再 `await persistence.saveNow()` 一次，使资产+节点+任务落在同一次文档写入里。Blob 已先落盘，所以中途崩溃最多留下孤儿 Blob（由 `gcBlobs` 清理）。
- `useAssetUrl(assetId): string | null` — url 源同步返回；blob 源加载中返回 `null`，之后返回 objectURL（按 blobKey 引用计数共享，最后一个使用者卸载时 revoke）；资产或 Blob 缺失返回 `null`。**UI 无法区分「加载中」和「缺失」**，两者都应显示占位。
- `gcBlobs(): Promise<number>` — 删除未被任何 Asset 引用的 Blob，返回删除数。目前未自动调度（见下）。

## 已知问题 / 限制
- jsdom 的 `Blob` 无法被 fake-indexeddb 结构化克隆，assetStore 测试改用 Node 原生 `Blob/File`（`node:buffer`）；真实浏览器无此问题。
- `resumeTasks()` 期间的文档变更会被保存（保存在 `resumeTasks` 前开启），但 `hydrated` 仍在其后才置 true。
- 读取 IndexedDB 失败时同样禁用保存（保守，避免覆盖可能可恢复的数据）。
- `gcBlobs` 未自动调用；若 `persistRemote` 之后 T4 失败/取消而未引用资产，资产仍在内存文档中（会被下次保存写入），其 Blob 仍被引用而不会被 GC —— 与「资产按引用保留」规则一致。

## 下一步建议 / 对其他任务的依赖假设
- T4：`resumeTasks()` 负责把过期 queued/running 转 `interrupted`；状态转换后调用 `persistence.saveNow()`。
- C3：用 `useSaveStatus()` 渲染；`error` 字段为错误信息。
- 节点组件：`useAssetUrl` 返回 null 时显示占位。
